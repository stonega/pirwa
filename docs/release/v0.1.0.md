# Pirwa v0.1.0

Pirwa's first public release is a native GNOME virtual machine manager for
Linux x86_64, built with GTK 4, libadwaita and libvirt.

## Features

- Discover local Session and System VMs, search the collection, and control
  power, pause/resume, CPU, RAM and installation media.
- Create Linux guests from local ISOs, copy standalone qcow2 images, and import
  supported stopped GNOME Boxes guests with their own copied storage.
- Use embedded or detached native SPICE consoles. VNC and SPICE GL consoles use
  the host's virt-viewer.
- Choose machine avatar presets, keep preferences between launches, and route
  supported Session guests through a manually configured host proxy.
- Try experimental Windows 10/11 profiles with user-supplied VirtIO driver media;
  Windows 11 requires host UEFI/Secure Boot and TPM 2.0 support.

## Downloads and installation

The release includes one standard `pirwa_0.1.0-1_amd64.deb`,
`pirwa-0.1.0-1.fc45.x86_64.rpm`, and
`io.github.stonega.Pirwa-0.1.0-x86_64.flatpak`, plus source/debug packages,
`release.json` provenance and `SHA256SUMS`.

```sh
# DEB systems with compatible GTK 4.16+ and other package dependencies
sudo apt install ./pirwa_0.1.0-1_amd64.deb

# Fedora 45, using COPR's signed repository builds
sudo dnf copr enable stonegate/pirwa
sudo dnf install pirwa

# Flatpak bundle; install the runtime from Flathub when prompted
flatpak install --user ./io.github.stonega.Pirwa-0.1.0-x86_64.flatpak
```

All formats need host KVM support for real guests. The Flatpak uses GNOME
Platform 51 and connects to host QEMU/libvirt; its host libvirt sockets must
already be active. Install host virt-viewer for external consoles, and host UEFI
and software TPM packages for guests that require them. See the
[package guide](https://github.com/stonega/pirwa/blob/v0.1.0/docs/release/publishing.md)
and [getting started](https://github.com/stonega/pirwa/blob/v0.1.0/docs/user/getting-started.md).

Verify downloaded assets with `sha256sum -c SHA256SUMS`. GitHub RPMs are
unsigned local builds; Fedora users can use COPR for signed packages.

## Known limitations

- Windows profiles are experimental; full Windows installation, driver and TPM
  persistence acceptance remains open.
- Real-host Flatpak System authorization, Boxes import, storage and proxy
  integration need broader validation. Host proxy routing supports IPv4 TCP and
  DNS for supported Session guests.
- Some startup and presentation measurements exceed project targets. Broader
  hardware, graphics-driver, audio and screen-reader coverage remains in progress.
- Snapshots, cloning, unattended installation, passthrough, remote management
  and multi-monitor guest consoles are outside this version's scope.

Existing VM definitions are discovered in place. Disk removal remains an explicit
operation restricted to storage proven to belong to Pirwa. The
[acceptance record](https://github.com/stonega/pirwa/blob/v0.1.0/docs/release/v0.1.0-readiness.md)
keeps the detailed evidence and remaining work.
