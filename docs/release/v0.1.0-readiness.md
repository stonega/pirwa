## Startup repair and current checks

The reported opening failure was reproduced in `scripts/run-dev.sh`: its
mandatory rebuild used cached include paths into SDK directories deleted from
`/tmp`. Compilation failed before launching the window. The current host now
uses development files in the ignored `.cache/dev-sdk/` directory, and Meson's
dependency cache has been cleared and reconfigured. The launcher also configures
a missing build directory and explains dependency recovery after a failed
rebuild. See [setup and recovery](../implementation/setup.md#launcher-fails-after-temporary-sdk-cleanup).

  pass. Launcher checks cover execution from another directory, argument

- All **nine isolated GNOME UI cases** pass, including light, narrow 200% text
  with dark appearance, empty inventory, Boxes discovery and console handoff.
  Raw result: `build/qa/startup-fix-20261116/report.json`.

  100 synthetic domains, inventory readiness and complete presented feedback.
  Raw result: `build/qa/startup-production-20261116/profile.json`. This is a

  desktop. Synthetic checks did not start or modify any existing guest.

The application object-lifetime checks pass; full GUI heap acceptance still
requires a fixed GTK build and assessment of the remaining font-stack reports.

## Collection performance continuation

The [row-menu follow-up](../research/collection-menus/README.md) removes eager
popover creation from VM binding. The menu is built on opening and discarded on
unbind, with its UUID, so recycled rows cannot retain another machine's targets.
Three alternating 1,000-domain scroll comparisons reduce paint CPU p95 from
19.5–21.3 ms to 5.1–5.5 ms. A separate 60-second idle sample records 49,024 KiB
PSS, 0.0159% CPU and zero paint frames; keep it separate from earlier sessions.

Thirty production launches per executable across alternating trials record
first-presentation p95 707.447 ms before and 607.657 ms after. Separate standalone
trials show a much smaller difference, so this is not a fixed per-launch saving.
Warm startup still misses 500 ms and virtual presentation intervals still miss
16.7 ms. Default renderer policy, host permissions and release budgets are unchanged.
The normal and sanitizer desktop matrices and 100-domain action checks pass.
The first sanitizer attempt exposed a test timing assumption: model updates can
precede GTK row unbinding. The corrected regression observes the factory's actual
unbind signal before checking discarded menus. The failed run is retained.
