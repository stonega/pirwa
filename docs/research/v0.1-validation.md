# v0.1 implementation validation

Implementation date: 2026-11-13. This is a development candidate, not a certified
0.1.0 release. The original bootstrap record remains historical.

## Passed locally

- Strict C17 build and eight default checks: inventory, backend, configuration,
  model reconciliation, provisioning/reference protection, two metadata checks,
  and 1,000-domain scale.
- Backend coverage: persistent state across commands, main-thread callbacks,
  pause/resume/shutdown/start/force stop, resource edits, safe definition removal,
  refusal to delete unowned disks, stale UUID failures, cancellation, stop,
  explicit reconnect, event-driven inventory, and console argument construction.
- Deterministic blocked-connect shutdown without a caller cancellable,
  monotonically ordered completions, request-correlated progress, and rejection
  of late/duplicate snapshots while preserving model object identities.
- Configuration coverage: XML escaping/roundtrip, CPU/RAM edits, ISO eject,
  invalid names/resource ranges, DTD rejection, standalone qcow2 headers,
  backing-chain and external-data feature rejection.
- Test-driver rollback checks retain running/shared disks and their definitions,
  accept missing unrelated media, detect symlink/hardlink/backing references,
  reject ambiguous XML, and preserve cancelled removals.
- AddressSanitizer + UndefinedBehaviorSanitizer on the default suite. Matching
  GCC runtimes were extracted locally. Leak detection was disabled; the prior
  libvirt initialization/TLS findings are not treated as resolved.
- Isolated real QEMU/KVM integration using Fedora's UEFI shell ISO: create/boot,
  late define failure and volume rollback, pause/resume, force stop, rename,
  CPU/RAM edits, eject, restart, verified disk removal, streamed qcow2 import,
  unchanged source image, and backing-chain rejection.
- Existing session VMs boxes-unknown and boxes-unknown-3 remained stopped.
  Shared-disk protection also rejected deletion when another VM used a symlink
  alias of the owned disk. The unique integration pool and its guests were removed after testing.
- Native Wayland tests and visual inspection of the production window, lifecycle
  actions, cancellation of destructive confirmation, settings/rename, stable
  selection, accessible header labels, search focus, and close with pending work.
- The same UI matrix passed in a disposable GNOME Shell 51.1 Wayland desktop
  with a 1280×800, 60 Hz virtual monitor: normal light, 200% font/dark at 720 px,
  and empty inventory. It also passed using address/undefined sanitizers
  (leak detection disabled). Primary creation buttons remain visible at 200%.
  This is programmed GTK action testing, not physical keyboard/mouse input,
  a screen-reader certification, or a guest console test.

See [hardening review](hardening-review.md) for the fixes, repeatable virtual
desktop command, screenshots, raw reports, and performance limitations.

The Fedora RPM built successfully, including its build-time test suite. It was
not installed. Runtime dependencies include virt-viewer, QEMU/KVM, and the
libvirt QEMU driver. Local BuildRequires checks were bypassed only because
matching development headers were extracted outside the system package database.

See benchmarks.jsonl for the measured synthetic inventories. The build mode is Meson release (-O3), on the same
Fedora 45 / Core Ultra 9 185H host as the bootstrap. It records both
the reconnecting async microbenchmark and persistent bulk reads with 0/100/1,000
domains. Do not compare the two methods as equivalent workloads.

## Remaining release acceptance

A full Linux install/reboot through the actual viewer, graphical input/audio/
resize/fullscreen and Wayland matrix, physical input/screen-reader checks, daemon
restart/permission fault injection, guest throughput comparison, cold/warm
presentation and scrolling traces, and acceptance of sustained idle CPU/PSS
measurements remain open. A backing-header check is not full qcow2 integrity certification.
Repeated startup under virtual GNOME also has an unresolved intermittent
readiness timeout, despite a subsequent complete 30-launch run. See the
hardening review before interpreting the successful UI matrix as a reliability
sign-off.

The host still needs normal installation of development dependencies and
virt-viewer for durable desktop use. Temporary extracted RPMs are not an SDK.

The AppStream schema check downgrades only url-homepage-missing to informational
because the project has no published homepage yet. Before public distribution,
publish the real homepage, choose a controlled application ID, add release
metadata/screenshots, remove that override, and complete the release gates.
