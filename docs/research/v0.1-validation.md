# v0.1 implementation validation

Implementation date: 2026-11-13. This is a development candidate, not a certified
0.1.0 release. The original bootstrap record remains historical.

## Passed locally

- Strict C17 build and nine default checks: inventory, backend, configuration,
  model reconciliation, provisioning/reference protection, two metadata checks,
  Boxes discovery/preferences, and 1,000-domain scale.
- Backend coverage: persistent state across commands, main-thread callbacks,
  pause/resume/shutdown/start/force stop, resource edits, safe definition removal,
  refusal to delete unowned disks, stale UUID failures, cancellation, stop,
  explicit reconnect, event-driven inventory, and console argument construction.
- Deterministic blocked-connect shutdown without a caller cancellable,
  monotonically ordered completions, request-correlated progress, and rejection
  of late/duplicate snapshots while preserving model object identities.
- Configuration coverage: XML escaping/roundtrip, CPU/RAM edits, ISO eject,
  invalid names/resource ranges, DTD rejection, standalone qcow2 headers,
  backing-chain and external-data feature rejection.
- Test-driver rollback checks retain running/shared disks and their definitions,
  accept missing unrelated media, detect symlink/hardlink/backing references,
  reject ambiguous XML, and preserve cancelled removals.
- AddressSanitizer + UndefinedBehaviorSanitizer on the default suite. Matching
  GCC runtimes were extracted locally. Leak detection was disabled; the prior
  libvirt initialization/TLS findings are not treated as resolved.
- Isolated real QEMU/KVM integration using Fedora's UEFI shell ISO: create/boot,
  late define failure and volume rollback, pause/resume, force stop, rename,
  CPU/RAM edits, eject, restart, verified disk removal, streamed qcow2 import,
  unchanged source image, and backing-chain rejection.
- Existing session VMs boxes-unknown and boxes-unknown-3 remained stopped.
  Shared-disk protection also rejected deletion when another VM used a symlink
  alias of the owned disk. The unique integration pool and its guests were removed after testing.
- Full Fedora Workstation 43 installation from ISO through the production
  creation form and real virt-viewer, graceful shutdown, Settings ISO eject,
  start from disk, first-run setup, and an installed GNOME desktop. The guest
  terminal confirms `/dev/vda3[/root]` with Btrfs as its root filesystem.
  Injected keyboard/pointer input and fullscreen switching worked in the private
  GNOME Wayland desktop. See the [installation record](linux-install/README.md)
  for screenshots, environment, audio-fixture correction, and cleanup results.
- Native Wayland tests and visual inspection of the production window, lifecycle
  actions, cancellation of destructive confirmation, settings/rename, stable
  selection, accessible header labels, search focus, and close with pending work.
- The same UI matrix passed in a disposable GNOME Shell 51.1 Wayland desktop
  with a 1280×800, 60 Hz virtual monitor: normal light, 200% font/dark at 720 px,
  and empty inventory. It also passed using address/undefined sanitizers
  (leak detection disabled). Primary creation buttons remain visible at 200%.
  This is programmed GTK action testing, not physical keyboard/mouse input,
  a screen-reader certification, or a guest console test.

See [hardening review](hardening-review.md) for the fixes, repeatable virtual
desktop command, screenshots, raw reports, and performance limitations.
The [Boxes onboarding validation](boxes-import/README.md) records first-run,
reopen, offline-library, and modal-close checks, plus the read-only preview of
the host's two native Boxes VMs. Actual Flatpak runtime/viewer validation is
still open; that branch has fixture coverage.

The Fedora RPM built successfully, including its build-time test suite. It was
not installed. Runtime dependencies include virt-viewer, QEMU/KVM, and the
libvirt QEMU driver. Local BuildRequires checks were bypassed only because
matching development headers were extracted outside the system package database.

The [console/performance follow-up](console-performance/README.md) records guest
resizing, injected capture/release/recapture, digital SPICE audio, and same-viewer
reconnect. It also records warm startup, 60-second idle CPU/PSS, large-collection
scroll CPU work, and paired real-KVM start overhead. Two guest-workload cohorts
and a manager-closed control expose substantial storage variance; that gate is
inconclusive and no guest throughput improvement is claimed.

See benchmarks.jsonl for the measured synthetic inventories. The build mode is Meson release (-O3), on the same
Fedora 45 / Core Ultra 9 185H host as the bootstrap. It records both
the reconnecting async microbenchmark and persistent bulk reads with 0/100/1,000
domains. Do not compare the two methods as equivalent workloads.

## Remaining release acceptance

The [metadata follow-up](release-metadata/README.md) establishes the owned
`io.github.stonega.Pirwa` identity while preserving the pre-release settings
storage path. Strict unsuppressed AppStream/tree validation, a real screenshot,
and source-version-aware RPM packaging now have 21 headless checks and ten
desktop cases per normal/sanitizer build, plus clean package verification.
Public URL/image reachability, committed-candidate CI and stable promotion
remain open; the canonical repository is currently private.

The [collection-menu follow-up](collection-menus/README.md) defers row menus
until opening and clears their targets on unbind. Three alternating 1,000-domain
scroll trials reduce paint CPU p95 from 19.5–21.3 ms to 5.1–5.5 ms. The matched
production warm-start p95 is still 607.657 ms and virtual presentation intervals
remain above 16.7 ms; hardware/cold-start acceptance stays open. The revised menu
regression waits for GTK's unbind signal and checks filtering, selection and UUID
targets in normal and sanitizer desktop runs, including a 100-domain fixture.

The [lifecycle and sanitizer startup follow-up](lifecycle-leaks/README.md)
fixes a reproduced test-driver backend reference leak. All 20 headless checks
now pass with leak detection enabled and a narrow, independently verified
libvirt initialization exception, including in a clean Fedora build. Private
QEMU recovery also passes with a clean leak-checked client exit. GUI leak
reports and the historical readiness timeouts remain separate open findings.

The [GUI ownership follow-up](gui-lifetimes/README.md) now verifies 32 window,
dialog, model and SPICE lifecycle cycles in both normal and ASan/UBSan builds,
with all 640 observed objects finalized per run. The desktop matrix includes
the new ownership case. Independent controls isolate the remaining growing
color allocation report to GTK 4.24.1; the Fontconfig component stays fixed
across 1/8/32 cycles. Full GUI heap acceptance remains open pending dependency
validation, separately from the passing application object-lifetime checks.
The stress checks also exposed a lost Settings-opening request during a
background inventory refresh. The fixed window preserves that intent only for
the same selected VM. The old code fails a deterministic injected refresh; the
fixed normal and sanitizer runs each pass 16 refresh and 16 selection-clearing
checks in 32 cycles. Ten desktop cases per build and a fresh clean RPM
build/install/verification pass with the fix. This does not identify the causes
of the older startup or Boxes readiness failures.

The [backend recovery follow-up](backend-recovery/README.md) adds deterministic
transport/permission fault injection, bounded retry and cancellation checks,
recovered storage-pool metadata, and a main-loop dispatch check during a blocked
inventory call. It fixes three reproduced recovery defects. This does not close
the real-daemon restart/polkit or Sysprof trace gates below.

The [private-daemon follow-up](backend-recovery/README.md#private-qemu-daemon-follow-up)
now verifies actual QEMU daemon startup failure, graceful/crash restart and Unix
socket denial/recovery in an empty isolated session, normally and with
ASan/UBSan. No existing service or guest is operated. The
[socket activation follow-up](backend-recovery/README.md#private-socket-activation-follow-up)
also verifies the first connection and restart recovery through `qemu:///session`
with pre-opened private sockets, in both builds. Installed systemd unit behavior,
system polkit and broader running-guest durability remain open.
The [Linux guest recovery follow-up](backend-recovery/README.md#running-linux-guest-follow-up)
now verifies continuing synced ext4 writes on virtio qcow2 through graceful/crash
daemon replacement, recovered pause/resume, clean offline filesystem/image checks
and persistence on reboot. It passed normally and with ASan/UBSan on the backend
client; a raw-disk control and interruption cleanup also passed. This fixture
does not certify other guest/storage combinations or SPICE continuity.

The [focus navigation follow-up](keyboard-navigation/README.md) verifies
search-focus restoration and programmed GTK modal/large-text focus traversal.
Experimental compositor input was not repeatable. Physical-input and
screen-reader acceptance remain open.

The broader guest/host console matrix, physical audio output/microphone/clipboard,
physical input/screen-reader checks, system authorization/socket activation,
stable guest storage acceptance, cold startup, presentation/scrolling and
backend-stall traces remain open. The idle CPU/PSS sample meets its provisional
100-domain budgets on this reference run. A backing-header check is not full
qcow2 integrity certification.
Repeated startup under virtual GNOME also has an unresolved intermittent
readiness timeout, despite a subsequent complete 30-launch run. See the
hardening review before interpreting the successful UI matrix as a reliability
sign-off.
The [Boxes readiness investigation](boxes-readiness/README.md) fixes a reproduced
test-harness defect: replacement windows used the closed window's frame observer
and could be driven before painting. Clock-identity and per-window paint checks
now cover that flow. The historical step-4 timeout was not reproduced, so its
precise cause and the broader readiness gate remain open.
The follow-up controlled scan test also reproduced and fixed machine controls
and creation being disabled during read-only Boxes discovery. It checks that
the guide waits behind Preferences or creation, with 18 GNOME cases and 14
headless checks passing per normal and ASan/UBSan build. This is separate from
the unresolved historical timeout; see the investigation's handoff record.

The host still uses extracted development files rather than normally installed
development packages. On 2026-11-16, the launcher failed because the old `/tmp`
SDK had disappeared. Its build now uses persistent `.cache/dev-sdk` paths; see
[startup repair and current checks](../release/v0.1.0-readiness.md#startup-repair-and-current-checks).
Normal package installation remains the recommended setup, including virt-viewer
for VNC/SPICE GL. The clean native check is separate from this host workaround.

Earlier development checks downgraded the missing-homepage warning. Current
checks use the owned ID and strict validation without an override, with project
URLs, snapshot metadata and a real screenshot prepared. Public page/image
reachability, stable-release metadata and the remaining release gates still need
acceptance before distribution.
