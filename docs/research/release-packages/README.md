## Fixes exposed by package builds

The Debian baseline lacks `GtkDropTarget`'s newer automatic cleanup typedef;
the UI test uses equivalent owned GObject cleanup. The growing embedded icon
set exceeded C's minimum string-literal size under strict warnings; generated
resource code now has its own compilation target with only that warning
disabled. Application warnings remain strict. Both native recipes package the
new avatar license and attribution files.

The newer GNOME SDK lacks SPICE's pyparsing build dependency and has a libxml2
API incompatible with the libosinfo release. The recipe pins a build-only parser
wheel and vendors upstream libosinfo commit
`0adf38535637ec668e658d43f04f60f11f51574f`. The source archive covers the patch;
other downloaded dependency sources have SHA-256 pins. Post-install paths use
Meson's build directory correctly.

The updated avatar preference regression exposed **617 leaked bytes in 15
allocations** under ASan. Two extra `g_variant_ref()` calls retained nested
preference dictionaries: GVariant's `@` constructor already retains non-floating
inputs. Removing those extra references makes the existing regression pass with
leak detection. No suppression was added for it. Native desktop checks also pass.

## Publishing setup and remaining acceptance

The empty [stonegate/pirwa COPR project](https://copr.fedorainfracloud.org/coprs/stonegate/pirwa/)
exists with Fedora 45 x86_64 and AppStream enabled. The private GitHub repository's
`release` environment and `COPR_CONFIG` secret are configured; only the secret's
name/presence was queried. No package was uploaded to COPR or GitHub Releases.

The workflow builds all formats from one source, assembles/verifies them, requires
a clean stable tagged commit, waits for copr-cli's build success, and then creates
the GitHub release with every asset. Manual dispatch builds artifacts only.
Actual hosted CI and a COPR rebuild await a reviewed committed release candidate.

The project remains private. Public project/screenshot reachability, real
Flatpak host Session/System authorization and storage/proxy/Boxes workflows,
physical input/audio/accessibility, performance misses, guest compatibility,
final review and release sign-off remain open in the
[readiness checklist](../../release/v0.1.0-readiness.md). Package tests do not
close those gates.
